# 12 — Notifications & reminders

## Purpose

Help users maintain habits: record reminders, goal updates, significant-increase alerts, plan
action reminders, challenge reminders, monthly/yearly summaries, and admin announcements.

## UI (Flutter)

| Screen | Elements |
|---|---|
| `NotificationsPage` | inbox, unread count, type filter, mark read/all, empty/loading/error |
| `NotificationPreferencesPage` | per-type toggles, local reminder time, save |
| `NotificationBell` | app-bar badge, deep link to the action |
| `LocalReminderScheduler` | opt-in local notifications |

States: loading, empty, success, unread/read, marking, permission denied, save failure.

## Screen logic (BLoC)

`NotificationsBloc`
- Events: `NotificationsStarted`, `NotificationRead`, `NotificationsReadAll`,
  `NotificationPreferencesSaved`.
- States: `NotificationsInitial`, `NotificationsLoading`, `NotificationsEmpty`,
  `NotificationsSuccess(list, unread)`, `NotificationsFailure`.

Local reminders are scheduled only after the user grants permission; in-app notifications always
work.

## Backend logic

| Method | Path | Auth | Purpose |
|---|---|---|---|
| GET | `/api/v1/notifications` | JWT | list own/broadcast |
| PATCH | `/api/v1/notifications/{id}/read` | JWT | mark one read |
| POST | `/api/v1/notifications/read-all` | JWT | mark all read |
| GET | `/api/v1/notification-preferences` | JWT | per-type prefs |
| PATCH | `/api/v1/notification-preferences` | JWT | update prefs |

Rules:
- Broadcast rows (`user_id null`) are visible to all; read state is per user (the implementation
  uses per-user copies or a read join — v1 creates per-user rows for simplicity).
- Types: reminder/goal/alert/plan/challenge/summary/announcement.
- Significant increase: `current > previous × (1 + threshold)` and absolute increase ≥ minimum.
- Respect preferences; announcements may override with a clear flag.
- Summaries are generated by a CLI/seed/admin action, not a background worker (local demo).
- Admin create/target is feature 15.
- Deep links use app routes; no tokens in URLs.

## Data

Tables: `notifications`, `notification_preferences`.
Invariants: user scoping; read state; type; bilingual title/body; no secrets.

## Acceptance criteria

1. A user sees own + broadcast notifications, newest first, with unread count.
2. Mark-one/mark-all works and persists.
3. Preferences disable a type without deleting history.
4. A significant-increase alert respects threshold + minimum.
5. Local reminders are scheduled only with permission; in-app works without it.
6. A notification deep-links to the relevant screen.
7. EN/AR and RTL are correct.
8. A user cannot read/mark another user’s notification.
